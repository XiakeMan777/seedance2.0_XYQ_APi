# 工程问题与规避（本机实测记录）

记录把「剪映小云雀 / Seedance」接入本地自动化时，实际踩到的问题、根因和规避方式。

## 1. 本地任务超时 ≠ 上游生成失败

- **现象**：本地任务在 1200 秒（20 分钟）被标记 `failed`，错误为「操作超时」，但上游其实还在排队。
- **根因**：默认 `TASK_TIMEOUT=1200`，而 Seedance 高峰期普通队列等待可达数小时（实测一次显示约 15881 秒 ≈ 4.4 小时）。
- **判定方法**：看上游 `RunQueueInfo`：
  - `task_status=8` / `task_progress` 有值 → 排队或生成中，**不是失败**
  - `expected_wait_time_seconds` 是排队预估；`vip_channel_target_expected_wait_time_seconds` 是 VIP 通道预估
  - `credit_consumption` 的 `pre_deduct_credits` / `actual_deduct_credits` 可判断是否真正扣费
- **规避**：把 `TASK_TIMEOUT` 调到 7200-10800。本仓库 `start.sh` 现在会自动读取项目根目录 `.env`。
- **注意**：本地超时后**不要立刻重提**，否则会再占一次队列；应先只读查询上游 thread。

## 2. 完成态取不到视频直链

- **现象**：上游 `state=3`（完成），但轮询一直取不到地址，直到本地超时。
- **根因**：小云雀视频直链**不含 `.mp4` 后缀**（形如 `https://v*.xyq-video.jianying.com/...?签名`），
  且藏在 `entry['artifact']['content'][i]['data']` 里——`data` 本身还是**一段 JSON 字符串**。
  原实现的正则要求 URL 含 `.mp4`，字段查找也没覆盖 artifact 结构，因此必然取不到。
- **规避**：新增 `_find_video_url()`：递归解析嵌套 JSON 字符串，只认显式 `video` 字段
  （`download_url` / `url` / `play_url` / `preview_url`），不做扩展名猜测。
- **验证**：用真实完成记录回放，`extract_video_url()` 命中 1 条。

## 3. Playwright 连不上已登录的 Chrome

- **现象**：`connect_over_cdp` 直接失败，报 `Browser context management is not supported.`
- **根因**：本机 Chrome 运行时暴露的 CDP 端点拒绝 `Browser.setDownloadBehavior`，而 Playwright 连接时必发该命令。
- **规避**：改用 `browser_cdp.py`，只调用确实可用的 `Target.*` / `Runtime.evaluate` / `Page.navigate`。
- **原则**：连接失败就明确报错，**不偷偷另起浏览器**；如需独立浏览器须显式 `ALLOW_BROWSER_LAUNCH=true`。

## 4. 积分被误读为 0

- **现象**：明明有积分却提示「积分不足」，无法生成。
- **根因**：`get_user_workspace` 已不再返回 `remain_credit`，原实现 `data.get('remain_credit', 0)` 把「字段不存在」当成 0。
- **规避**：改为只读页面上的积分徽标；读不到时返回 `null`，**不要返回 0**。

## 5. 账号能力不要擅自删改

- **教训**：为「只用本人账号」而移除上游的多账号 Cookie 轮换，是不该做的取舍。
- **做法**：新增能力走**可选增量**；原有默认行为与全部原功能保留，切回方式写进 README。

## 6. 隐私与凭证

- `cookies/`、`data/`、`logs/`、`run/`、`.env` 必须留在 `.gitignore`，不要提交。
- 提交 / 推送 / 提 PR 前自查：Cookie、密钥、账号 ID、积分、本机绝对路径是否进入内容。
- Git 提交作者邮箱来自本机 `git config`，会随公开提交一起公开。

## 7. 运维速查

```bash
./.venv/bin/python debug_credit.py                  # 只读看登录与积分
curl -s http://127.0.0.1:8033/api/account/status    # 只读账号状态
curl -s http://127.0.0.1:8033/v1/models             # 可用模型
tail -f logs/xyq-seedance.launchd.log               # 运行日志
```

只读查询上游任务（不重提、不换账号）：用 `get_thread` 接口按 `thread_id` 读取 `run_list`。

## 8. 上游记账与实际扣减可能不一致

- **现象**：一次 5 秒 Fast 生成，上游 `credit_consumption.actual_deduct_credits` 记的值，
  与账号余额实际减少的量**对不上**（实测相差约 6%）。
- **规避**：对账以**账号余额实测**为准；上游记账字段只作参考，两者不一致时并列记录，
  不要强行归一。文档 / 提交里**不要写入具体积分数字**（属账号数据）。

## 9. `estimated_time_seconds` 不是倒计时

- **现象**：生成期间该值会反复跳变（实测在 1 ~ 201 秒间来回变），且可能长时间不动。
- **规避**：只当作上游的粗略估计。判断进度看 `state`
  （1 排队 / 2 生成中 / 3 完成 / 4 失败），不要据此推算剩余时间，也不要据此决定是否重提。
